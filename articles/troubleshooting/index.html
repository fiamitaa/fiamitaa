“明明已经连接成功，为什么网页还是打不开？”

遇到这种情况，先换节点、再换软件、最后重装，很容易越改越乱。浏览器没有使用代理，或者 DNS 和连接走了不同路径，都可能让问题看起来像“工具坏了”。

先看看“连接成功”究竟指哪一步。不同客户端的状态含义不同：“已启动”可能只是本地核心在运行，“延迟测试成功”也可能只验证了某个测试目标。它们都不能单独证明你要访问的网站可达，更不代表所有应用都在使用这条连接。

第一步：确认问题范围

先观察是一个网站打不开，还是所有网站都打不开。

如果只有一个网站失败，可能是目标网站自身故障、域名解析问题、地区限制、账号风控或网站拒绝某类出口 IP。如果所有网站都失败，更应该检查客户端状态、系统网络、路由和 DNS。

再看失败方式：

  • 立刻提示无法连接，可能是域名或端口问题；
  • 一直转圈后超时，可能是丢包、线路不通或服务器无响应；
  • 页面能开但图片和脚本失败，可能是分流、DNS 或内容域名没有走同一路径；
  • 登录后频繁验证，可能是出口变化触发了网站的安全策略；
  • 只有一个应用失败，可能是应用没有使用系统代理。

把具体错误提示记下来，通常比只描述“感觉不稳定”更有排查价值。

第二步：确认客户端真的在工作

检查客户端是否显示连接成功、配置是否过期、设备时间是否正确，以及系统是否弹出过权限或网络扩展提示。有些系统级 VPN 需要用户明确允许网络扩展；权限没有生效，界面却可能仍然保留“已启动”的状态。

如果客户端提供连接日志，可以看是否出现认证失败、证书错误、DNS 错误、路由冲突或反复重连。新手不必读懂每一行，只要注意重复出现的关键词。

还要确认是否同时运行了多个代理工具。两个程序都试图接管系统网络时，可能互相覆盖配置，表现为连接成功但访问异常。

如果需要请别人协助，可以先记录四项：系统与客户端版本、出错的应用、完整错误提示、问题发生时间。分享日志前删去订阅链接、密钥和账户信息。比起一句“连不上”，这些信息更能帮助定位问题。

第三步：区分系统代理、浏览器代理和应用代理

代理不是一个开关，而是一组可能分散在不同位置的设置。

  • 浏览器代理只影响浏览器；
  • 系统代理可能影响遵循系统设置的应用；
  • 分应用代理只让指定程序走代理；
  • 某些应用完全不读取系统代理，而是使用自己的网络栈；
  • 全局 VPN 通常影响范围更大，但也可能有排除规则。

因此，浏览器能访问而桌面应用不能访问，并不矛盾。先确认失败的应用到底采用哪种网络设置，再决定是否需要调整配置。

第四步：检查 DNS 和后续连接

DNS 负责把域名转换成 IP 地址。解析错误时，网页当然无法正确连接；但 DNS 正常，也不代表后续 TCP、TLS 或应用层连接一定成功。

排查时可以观察：域名是否能解析、解析结果是否频繁变化、浏览器是否提示证书错误。不要为了追求“能打开”而随便关闭证书校验或安装不明根证书。那可能绕过了一个提示，却把更大的中间人风险带进来了。

第五步：看速度、延迟和丢包

如果网页不是完全打不开，而是迟迟加载不完，就要把速度、延迟和丢包分开看。速度主要受带宽、服务器负载和目标网站响应影响；延迟会影响实时通信和交互；丢包则会让页面反复重传，看起来像完全打不开。

做机场测速时，区分延迟测试、下载速度和目标网站的实际访问。节点延迟低，不代表高峰期下载快，也不保证某个网站允许这个出口访问。比较结果时，尽量固定设备、网络和测试目标，并记下测试时间。

同一个服务在不同时间、不同地区和不同网络运营商下表现不同，并不一定说明客户端坏了。可以分别试试普通网页、静态文件、视频和实时应用，看看问题集中在哪一类。不要只用一个网站就判断整个网络。

第六步：考虑网站的风控和兼容性

网站看到异常的出口位置、频繁切换 IP 或大量并发请求时，可能触发验证码、登录验证或临时封禁。这不是网络工具一定“失效”，而是网站在保护账号和服务。

遇到这种情况，不要不断切换出口，也不要关闭安全验证。先确认账号状态，按照网站提供的恢复流程处理。Tor Project 的安全说明也提醒，服务可能因出口位置变化而要求额外验证。[1]

一份简短排查顺序

可以按下面的顺序来：

  1. 判断是单个网站、单个应用，还是全部网络失败；
  2. 查看客户端状态和日志；
  3. 确认系统、浏览器和应用到底使用哪种代理；
  4. 检查 DNS、证书和设备时间；
  5. 区分速度、延迟、丢包和网站风控；
  6. 仍然无法判断时，恢复到单一配置，避免多个工具叠加。

一次只改一个变量，并记录改动前后的结果。如果同时换节点、DNS 和规则，即使恢复访问，也很难知道是哪一步起了作用。
