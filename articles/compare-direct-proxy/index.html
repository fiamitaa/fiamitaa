同一个网站，直连和代理结果怎么对照？

固定网址，对照连接过程、响应和退出码，定位请求在哪一步失败。

浏览器能打开，终端却超时，先别同时换节点、DNS 和客户端。用 curl 对同一个网址分别发起“跳过显式代理”和“指定代理”的请求，看失败停在哪一步。

下面适用于当前 Windows 11 的 PowerShell、macOS 的终端，以及 Ubuntu 桌面或服务器终端。示例使用本机 HTTP/Mixed 端口 127.0.0.1:7890，请替换为客户端实际端口。命令不会修改系统代理，测试结束无需恢复设置。

先控制测试条件

保持同一台设备、同一个网络和同一个目标网址。先运行代理客户端，记录测试时间。https://example.com/ 是示例目标，排查某个网站时，将两条命令中的网址一起替换为该站的公开页面，不要使用带登录令牌的链接。

命令中的 -q 放在首个选项位置，用于忽略默认 curl 配置文件；--noproxy "*" 跳过 curl 显式代理，--noproxy "" 清除本次请求的代理例外。已有 curl 配置或 NO_PROXY 可能改变请求路径，这几个选项用于排除它们的干扰。[1]

跳过 curl 代理，不等于绕过系统 TUN、VPN 或路由器代理。 如果这些接管方式正在运行，两次请求仍可能经过同一个上游。需要比较基础网络时，先记录现状，在允许中断连接的情况下暂时停用相关接管，测试后恢复；不要在远程维护会话中贸然断开承载会话的 VPN。

Windows：在 PowerShell 中运行

开始菜单搜索“终端”，打开 PowerShell 标签页。先确认使用 curl 程序，而不是旧版 PowerShell 的同名别名：

curl.exe --version

先执行跳过代理的请求：

curl.exe -q --noproxy "*" --connect-timeout 10 --max-time 30 -v https://example.com/ -o NUL
$LASTEXITCODE

再指定本机 HTTP 代理。每条 curl 命令后立即读取退出码，别在中间执行其他命令：

curl.exe -q --noproxy "" --proxy http://127.0.0.1:7890 --connect-timeout 10 --max-time 30 -v https://example.com/ -o NUL
$LASTEXITCODE

这里使用当前 PowerShell 7 的参数传递方式。如果你使用 Windows PowerShell 5.1，空字符串参数传递可能不同，可将第二条命令改为以下写法，避免传递空参数：

curl.exe -q --noproxy example.invalid --proxy http://127.0.0.1:7890 --connect-timeout 10 --max-time 30 -v https://example.com/ -o NUL
$LASTEXITCODE

example.invalid 是这里专门设置的不匹配例外，测试网址不要改为这个域名。Windows 11 内置 curl；若找不到程序，用 where.exe curl 核对路径，再检查系统组件或从 curl 官方渠道安装。[2]

macOS：在终端中运行

按 Command + 空格，搜索“终端”并打开。检查 curl：

curl --version

先跳过 curl 代理，再指定代理，每次执行后立即查看退出码：

curl -q --noproxy "*" --connect-timeout 10 --max-time 30 -v https://example.com/ -o /dev/null
printf 'exit=%s\n' "$?"

curl -q --noproxy "" --proxy http://127.0.0.1:7890 --connect-timeout 10 --max-time 30 -v https://example.com/ -o /dev/null
printf 'exit=%s\n' "$?"

如果命令不存在，先确认终端路径和 curl 安装情况。无需为了这次测试修改 macOS 的网络代理开关。

Ubuntu：在终端中运行

桌面版按 Ctrl + Alt + T；服务器版直接使用当前 shell。先检查工具，缺少 curl 时再安装：

curl --version

sudo apt update
sudo apt install curl

执行两次请求，保持网址与端口一致：

curl -q --noproxy "*" --connect-timeout 10 --max-time 30 -v https://example.com/ -o /dev/null
printf 'exit=%s\n' "$?"

curl -q --noproxy "" --proxy http://127.0.0.1:7890 --connect-timeout 10 --max-time 30 -v https://example.com/ -o /dev/null
printf 'exit=%s\n' "$?"

安装需要管理员权限，测试请求本身不需要 sudo。APT 安装失败时先处理软件源或基础联网问题，不要把安装失败当成 curl 测试结果。[3]

对照时看什么

-v 显示连接过程，网页正文被丢弃。指定代理的请求，应先看到连接本机代理地址；HTTPS 目标还可能显示 HTTP CONNECT 隧道响应，然后才是目标站点的 TLS 握手和 HTTP 响应。

对照结果 下一步
两次都成功 这次目标在两条 curl 配置下都可访问，不能据此判断其他应用
跳过代理成功，指定代理失败 先看是否连上本机端口，再查代理握手和上游连接
跳过代理失败，指定代理成功 当前两条请求路径表现不同，继续核对 DNS、路由或访问限制
两次都失败 对照具体阶段；相同错误也可能来自目标站点或基础网络

退出码 0 表示 curl 传输完成，不保证 HTTP 状态是 200。未加 --fail 时，收到 403、404 等响应也可能退出为 0。代理返回的 200 Connection established 只表示隧道建立，后面仍可能 TLS 失败。[1]

--connect-timeout 10 限制连接阶段，--max-time 30 限制整次请求，单位都是秒。超时后记录报错即可，不需要不停重试。若两次结果矛盾，可在相同条件下再各执行一次，排除偶发波动；它们不是测速数据。

需要 SOCKS5 时，将代理地址换成 socks5h://127.0.0.1:实际端口，其余条件保持不变。解析位置的区别见 SOCKS5 代理验证。分享结果前遮住认证头、账号、内网地址和敏感网址。
