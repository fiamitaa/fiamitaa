怎么用 curl 验证 HTTP 代理？Windows、macOS 和 Ubuntu 操作步骤

用 Windows、macOS 或 Ubuntu 的 curl 检查本机 HTTP 代理端口。

本机客户端显示代理已启动，怎么确认端口真的能转发请求？可以用 curl 发起一次明确指定代理的请求，再对照返回结果。下面分别说明 Windows、macOS 和 Ubuntu 的操作。示例使用本机 HTTP 代理 127.0.0.1:7890；如果你的客户端监听在其他地址或端口，请替换成实际值。

先确认代理地址

这里测试的是本机代理入口，不是机场订阅里的服务器地址。常见客户端会在设置或日志中显示 HTTP/Mixed 监听端口。若客户端只提供 SOCKS5 端口，请使用下一篇的 SOCKS5 命令。

先确认客户端正在运行，并找到 HTTP 或 Mixed 端口。不要把订阅链接、密码或节点密钥填进命令，也不要把包含凭据的日志直接发到公开论坛。

Windows

打开 PowerShell。Windows 10/11 通常自带 curl.exe；使用带 .exe 的命令名，可以避免 PowerShell 把 curl 解析为旧版命令别名。

curl.exe -v --proxy http://127.0.0.1:7890 https://example.com/ -o NUL

查看输出中的 Connected to 127.0.0.1 ... port 7890，确认 curl 已连接本机代理端口。接下来会看到 TLS 握手及 HTTP 响应状态；example.com 返回网页说明这次请求完成。-o NUL 会丢弃网页正文，-v 用于显示连接过程。

如果提示 Could not connect 或 Connection refused，先检查客户端是否运行、端口是否填对。若提示 curl.exe 找不到，可在 PowerShell 执行 where.exe curl 检查系统是否安装并能找到 curl；也可以从 Windows 官方文档了解系统自带 curl 的情况。[1]

macOS

打开“终端”（Terminal），先检查 curl 是否可用：

curl --version

能显示版本信息就继续测试；若提示找不到命令，先从 Apple 或可信的软件包管理渠道安装 curl，再确认终端能找到它。

执行测试：

curl -v --proxy http://127.0.0.1:7890 https://example.com/ -o /dev/null

macOS 自带 curl。确认输出连接到 127.0.0.1 的 7890 端口，并查看后续 TLS 与 HTTP 状态。/dev/null 会丢弃网页正文。

若系统提示证书验证失败，先核对系统日期时间和目标网址，不要用 -k 跳过证书检查。若连接本机端口失败，回到客户端核对 HTTP/Mixed 端口与监听地址。

Ubuntu

打开终端。若系统没有安装 curl，先安装发行版仓库提供的包：

sudo apt update
sudo apt install curl

然后执行测试：

curl -v --proxy http://127.0.0.1:7890 https://example.com/ -o /dev/null

确认连接日志指向本机的 7890 端口，并检查 TLS 握手及 HTTP 状态。Ubuntu 的 APT 包管理器使用 apt install 安装 curl；如果你的环境由组织管理，按管理员提供的软件源和权限要求操作。[2]

怎么读结果

  • 连接本机端口失败：客户端未启动、端口错误，或服务没有监听在 127.0.0.1。
  • 连接成功但随后报错：本机代理入口可达，继续看报错发生在 TLS、DNS 还是目标站点响应阶段。一次测试不能单独证明所有网站都可访问。
  • 收到 HTTP 状态码：说明请求已经得到 HTTP 层响应；200 通常表示示例页面成功返回，其他状态码要结合目标站点含义判断。

想对照直连，可以去掉 --proxy http://127.0.0.1:7890 再执行一次。保持网址不变，比较两次输出里的连接阶段。是否直连成功取决于当前网络与目标站点，不能把它当成代理端口可用与否的唯一依据。

这项测试只检查 curl 这条命令。浏览器或其他应用是否使用代理，还要分别观察它们的设置或客户端连接日志。
