代理、VPN、Tor 有什么区别：覆盖范围与信任关系

从覆盖范围、信任关系与隐私目标，理解三种不同的网络工具。

代理、VPN、Tor 经常一起出现在“如何访问某些网络服务”的讨论里。对新手来说，它们看起来都像是在做同一件事：让请求绕一个弯。

它们确实都涉及流量转发，但覆盖范围、信任关系和隐私目标不同，适合的场景也不一样。

“机场 VPN”这个叫法容易让人混淆服务类型。机场通常指提供代理订阅和节点的服务，VPN 则描述一种隧道技术或相应服务。判断它们会接管哪些流量，还要看客户端的运行模式和实际配置。

代理：一个中转站

代理可以理解成“替你向目标网站发请求的中间人”。你的浏览器或某个应用先把请求交给代理服务器，代理再访问目标地址，把结果返回给你。

HTTP 代理常用于网页请求，也能通过 CONNECT 方法建立隧道；SOCKS5 则定义了连接转发与 UDP 转发等机制。具体应用和服务器支持哪些能力，仍要看实现，不能简单理解为“HTTP 代理只能打开网页”。[4][5]

它们都可以按应用配置。例如，只让浏览器经过代理，其他软件仍然使用原来的网络路径。

不过，只给浏览器配好代理，不代表其他程序也能用。代理可能只对一个应用生效，某些应用还有自己的网络设置，完全不理会浏览器代理。于是就会出现“网页能开，但桌面客户端还是连不上”的情况。

代理还带来一个信任问题：请求经过谁的服务器？对方保存什么日志？是否修改内容？如果代理服务商没有清晰的运营主体和隐私说明，就不适合拿来处理重要账号或敏感资料。

VPN：一条加密隧道

VPN 的常见工作方式，是在设备与 VPN 服务器之间建立一条加密隧道。设备的部分或全部网络流量经过隧道转发，再从 VPN 服务器访问互联网。

它的覆盖范围通常比浏览器代理更大，能够影响多个应用，甚至整个系统的网络出口。对于公共 Wi-Fi、远程办公或访问企业内网，VPN 也有正常且广泛的使用场景。

但“VPN 有加密”不等于“VPN 让你完全匿名”。你把一部分网络信任从本地网络转移给 VPN 服务商。VPN 服务器会解开 VPN 这一层隧道；如果里面还使用了正常校验的 HTTPS，网页内容仍受 HTTPS 保护。没有应用层加密的内容，则不能指望 VPN 自动保护到目标网站。

即使读不到 HTTPS 正文，服务商仍可能接触到连接时间、流量规模和目标 IP 等元数据；如果你登录网站，网站也仍能关联到你的账户。

VPN 更适合解决“让一组应用通过另一条网络路径访问”的问题，而不是承诺消除所有身份线索。

Tor：多层中继网络

Tor 通过多个中继节点转发流量。Tor Project 的介绍通常把它概括为：连接经过多个中继，每一层只知道自己需要知道的那一部分，从而降低单个观察者同时把用户和目标网站对应起来的可能性。[1]

Tor Browser 不是普通浏览器简单加一个代理。它基于 Firefox ESR，并针对隐私、浏览器指纹和会话管理做了专门修改。Tor Project 也不建议把其他浏览器随意接到 Tor 网络上，因为浏览器配置、插件和应用行为可能造成信息泄露。[2]

Tor 的代价也很明显：多跳转发会增加延迟，部分网站会把 Tor 出口视为高风险来源，要求额外验证，甚至拒绝服务。它更偏向隐私和匿名性场景，不是追求视频速度或低延迟游戏体验的万能方案。

三者放在一起怎么比较

维度 代理 VPN Tor
覆盖范围 常见是单个应用 可覆盖多个应用或全局流量 主要是配置正确的应用，Tor Browser 最稳妥
速度 取决于线路、负载与实现 取决于线路、负载与实现 多跳转发通常增加延迟
信任对象 代理运营者 VPN 服务商 多个中继运营者和 Tor 网络机制
主要目标 转发和访问路径 隧道、远程访问、网络出口变化 降低单点关联和追踪风险
常见误区 以为所有应用都会走代理 以为 VPN 等于匿名 以为 Tor 能保护整台设备所有流量

怎么按需求思考

如果你的问题是“某个浏览器访问不了”，代理可能是最小范围的解决思路；如果希望多种应用都通过同一条加密连接，VPN 更接近这个需求；如果重点是降低网站和本地观察者之间的直接关联，Tor 的设计目标更相关。

很难脱离需求，说哪个工具“最强”。工具越复杂，需要留意的配置细节就越多，也越容易误用。Tor Project 明确提醒，Tor Browser 只保护经过正确配置的应用，不会自动保护电脑上所有程序。[3]

先问自己三个问题：

  • 我需要改变哪一个应用的访问路径？
  • 我更在意速度、兼容性，还是隐私？
  • 我是否清楚自己把信任交给了谁？
