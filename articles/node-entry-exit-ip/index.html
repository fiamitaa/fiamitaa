代理节点入口和出口 IP 为什么不同？

沿着一次请求分清节点配置、客户端连接地址和网站观察到的出口。

约 3 分钟阅读内容复核 2026.11.20

订阅列表里的节点名称、客户端实际连接的地址、网站看到的出口 IP，有时是三件不同的事。可以沿着一次请求把它们区分开。

顺着一次访问看三个位置

应用 → 本地客户端 → 服务入口 → 可能的内部转发 → 出口 → 目标网站

这是一种路径示意。服务只有一台转发服务器时，入口和出口可能在同一台机器上，仍可能使用不同地址。有些服务会把接收客户端连接和访问目标网站交给不同机器。

名称 在哪里看 能说明什么
节点 客户端的配置或选择列表 一组连接参数，包括名称、服务器和端口等
入口 客户端建立远端连接的位置 当前连接使用哪个服务地址
落地 服务说明或内部拓扑 通常指负责后段转发的机器或环节，具体含义由运营方定义
出口 IP 目标网站看到的连接来源地址 这次请求抵达目标时使用的网络地址

Mihomo 官方文档分别定义了节点的名称、服务器域名或 IP、端口，也支持经由另一出站建立连接。[1] 因此，配置里看到的服务器地址和实际目标看到的来源地址，可能指向路径上的不同位置。

为什么换节点以后，出口可能没变

可以设想两条线路使用不同入口，最后经由同一个出口访问网站。客户端切换了节点，网站仍会看到相同的出口。另一种情况是查询页命中了直连规则，切换代理组时，这个页面的路径没有变化。

想分清这两种情况，可以固定设备、网络和查询目标，依次选中候选节点。每次发起新请求，并确认日志里记录的规则和出站。若查看的是之前就已建立的连接，先确认应用确实发起了新的连接，再比地址。

用出口查询回答对应的问题

查询页适合回答“这个网站这次看到什么地址”。它通常看不到服务内部的转发位置。页面显示的地区也需要结合服务商的说明理解，节点名称和查询标签都不足以单独证明服务器的物理位置。

同一个地址也只代表这次连接的可见来源。部分 HTTP 代理可以通过转发头附带客户端信息，网站也能根据登录状态识别账号。[2] 如果你要解决的是“为什么某网站表现不同”，先把应用、目标、命中规则和时间记下来，出口 IP 可以和这些信息一起比较。
