怎么用 curl 验证 SOCKS5 代理？Windows、macOS 和 Ubuntu 操作步骤

分平台验证 SOCKS5 端口，并比较本地与代理端 DNS 解析。

如果客户端提供的是 SOCKS5 端口，可以用 curl 明确指定代理，检查连接是否经过这个本机入口。Windows、macOS 和 Ubuntu 的操作基本相同，主要区别在终端和 curl 的安装方式。下面使用 127.0.0.1:7891 作为示例地址，请按客户端实际监听端口替换。

先区分 SOCKS5 和 SOCKS5 主机名解析

curl 支持 socks5:// 和 socks5h:// 两种写法：前者由本机解析目标域名，后者把域名交给 SOCKS5 代理端解析。测试代理转发时，建议先用 socks5h://，这样能明确要求代理端处理目标主机名；如果要检查本地 DNS 路径，再改用 socks5:// 做对照。[1]

下面都测试 HTTPS 网站。命令里的 SOCKS5 代理只是连接到客户端的本机入口，不要把带账号密码的节点分享链接贴进命令或截图。

Windows

打开 PowerShell，执行：

curl.exe -v --proxy socks5h://127.0.0.1:7891 https://example.com/ -o NUL

使用 curl.exe 可避免 PowerShell 中 curl 名称被旧版别名占用。查看输出，确认 curl 连接到了本机 7891 端口，之后继续出现 TLS 握手与 HTTP 响应。Windows 10/11 可先试用系统自带 curl；若命令不存在，用 where.exe curl 检查路径。[2]

若客户端的 SOCKS5 端口不是 7891，替换命令中的端口。不要把“HTTP 代理端口”误填到这里，除非客户端明确说明该端口同时支持 SOCKS5。

macOS

打开“终端”（Terminal），先检查 curl 是否可用：

curl --version

能显示版本信息就继续测试；若提示找不到命令，先从 Apple 或可信的软件包管理渠道安装 curl，再确认终端能找到它。

执行测试：

curl -v --proxy socks5h://127.0.0.1:7891 https://example.com/ -o /dev/null

macOS 自带 curl。连接日志先确认本机 SOCKS5 端口可达，再看 TLS 与 HTTP 状态。若停在连接本机代理这一步，优先核对客户端监听端口；若本机连接成功但域名解析失败，可再做 DNS 对照。

Ubuntu

打开终端。若没有 curl，安装系统仓库中的版本：

sudo apt update
sudo apt install curl

然后执行：

curl -v --proxy socks5h://127.0.0.1:7891 https://example.com/ -o /dev/null

确认输出连接到 127.0.0.1 的 7891 端口，并观察后续 DNS、TLS 与 HTTP 结果。使用受管理的 Ubuntu 设备时，按设备管理员的权限和软件源要求安装。[3]

对照代理端与本机解析

保持代理地址和测试网址不变，只把协议前缀改为 socks5://：

curl -v --proxy socks5://127.0.0.1:7891 https://example.com/ -o /dev/null

Windows PowerShell 同样使用 curl.exe，并把输出目标换成 NUL。如果 socks5h:// 可以完成请求，而 socks5:// 失败，问题可能与本机 DNS 解析路径有关；这只是排查线索，还需结合 curl 错误、系统解析结果和客户端日志确认。

两种写法都失败时，先看失败阶段：连不上本地端口，检查客户端及监听设置；本机端口已连上、但代理端返回错误，再检查 SOCKS5 服务是否可用、目标域名能否解析，以及目标网站是否响应。curl 的结果只代表这次命令、这个目标和当前网络。

如果要和直连比较，去掉 --proxy socks5h://127.0.0.1:7891 后重试。不要同时更换 DNS、代理端口和目标网址，否则结果难以对照。
