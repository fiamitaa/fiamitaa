配置、订阅、节点与规则：看懂客户端里的那些词

导入订阅、选择节点和设置分流，分别改变了什么？

安装客户端只是开始。真正让客户端工作的，通常是一份配置。配置里可能有服务地址、认证信息、协议参数、代理组、DNS 和分流规则。

“机场订阅”通常是服务商提供的配置获取入口，“机场节点”则是配置中的具体连接条目。一份订阅可以包含多个节点；更新订阅和切换节点，也不是同一个操作。

节点是什么

节点通常指一个可以接收代理连接的远程服务入口。它可能包含地址、端口、协议、认证信息和传输参数。

节点不是客户端，也不是协议。它背后通常由某个服务商、个人或组织运营。流量经过它，就需要考虑运营者的可信度、日志政策、稳定性和适用规则。

配置文件是什么

配置文件把客户端需要的参数组织起来，可能描述：

  • 核心需要的运行参数；
  • 连接哪些节点；
  • 采用什么协议；
  • 哪些域名直连；
  • 哪些流量经过代理；
  • DNS 如何处理；
  • 代理组如何选择。

不同核心支持的配置格式可能不同。文件能导入，只说明它被读取，不说明每个字段都生效。

订阅链接是什么

订阅链接通常不是软件本体，而是获取或更新配置的地址。客户端访问订阅后，得到节点列表、规则或其他配置内容。

订阅链接往往带有访问权限，不能公开发布。它可能被他人使用，也可能暴露账户信息。发现泄露时，应优先撤销、重置或更换。

同一个订阅链接，下周返回的配置可能就和今天不同。自动更新省去了手动下载的步骤，却不能替你判断内容是否安全。更新前要确认来源，更新后也要留意配置是否有异常变化。

代理组和规则

代理组把多个节点或策略放在一起管理。规则则决定一类流量直连、代理还是拒绝。

常见模式包括：

  • 直连模式：将核心接收到的流量按直连策略处理；
  • 全局模式：将核心接收到的流量交给指定代理策略；
  • 规则模式：对核心接收到的流量，按域名、IP 或其他条件选择路径。

这三种模式决定的是“流量进入核心后怎么处理”，不是“哪些应用已经进入核心”。例如，浏览器使用系统代理、某个桌面应用不读取系统代理时，切到全局模式也不会自动把后者接进来。

TUN 是另一层设置：它通常通过虚拟网络接口与路由接收流量，影响范围还取决于系统权限、路由和排除规则。打开 TUN 不代表可以跳过这些检查。[1]

规则越复杂，排查越困难。新手最好先从简单配置开始，不要一次叠加很多第三方规则集。

DNS 为什么会影响结果

DNS 请求可能走本地网络、代理隧道或特定解析服务。解析路径和访问路径不一致时，可能出现域名能解析但目标连不上，或者网页能开、部分资源失败。

这也是同一份订阅在不同客户端上表现不同的原因之一：客户端可能调用不同核心，使用不同 DNS 模式、缓存和规则引擎。

配置的安全风险

配置文件可能包含订阅链接、密钥、密码、服务器地址和个人账户标识。不要将完整配置上传到公共代码仓库，也不要把二维码和订阅链接发到公开群组。

遇到陌生配置，尤其要谨慎。如果导入或使用时要求你关闭安全软件、安装不明证书、运行脚本或输入系统密码，先停下来，核实这些要求的来源和用途。

排查时也按这些角色区分：导入失败，先检查格式与客户端支持；某个节点连接失败，查看对应连接日志；只有部分网站走错路径，再查规则与 DNS。不要一遇到问题就把整份配置全部换掉。
